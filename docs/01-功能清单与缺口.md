---

## 0. 一句话

私聊发 **Linpx 小说 / 系列 / 作者链接** → 按**作者**做名单校验 → 回传 `txt` / `zip` → 可一键分享到频道；未收录的作者走「用户申请 → 中转频道 → 管理员核验」。

当前是「**按作者授权 + 人工审核**」模式：**没有**基于标签 / 正文的自动识别，**没有**翻译。

## 2. 不能做什么（缺口）

### P0 · 影响可用性或运营安全

| 问题 | 表现 | 位置 |
|---|---|---|
| ~~分享提示与实际目标不一致~~ | ✅ 已修：文案按 `ShareResult.channels` 渲染，目标频道由 `SHARE_MODE` 决定 | `callbacks/share.py`、`share_service.py` |

### P1 · `Upgrade.md` 已规划但未实现

| 缺口 | 说明 |
|---|---|
| 白名单未接入 | 产品决定暂不使用：`AuthorPolicy` 只读黑名单与兽人作者名单 |
| 分享发正式频道 | ✅ 已支持 `SHARE_MODE=prod`：高分发兽人阅读 + 兽人小说，低分 / 未评分只发兽人小说；评分本身仍未实现 |
| 标签 / 正文过滤 | 无自动兽人识别，全靠人工 |
| 作者自助拉黑 | 无投诉通道，只能管理员在审核卡片上点「拉黑」 |
| 历史分享下架 | ⚠️ 能力已就绪（`TakedownService` + 记录带 `message_id`），但没有入口：等「作者申请下架」流程定了再接 |
| 翻译 | 完全未实现 |
| 中转频道存待审文件 | 只有文字卡片，没有作品文件 |

### P2 · 工程质量

| 问题 | 影响 |
|---|---|
| `__pycache__` 未加入 `.gitignore` | 容易误提交 |
| `/start` 文案仍是「这是一个空壳 Bot」 | 第一印象错误 |
| 无 lint / format / type 配置 | tab 与空格混用 |
| `pytest` 列在运行时依赖 | 生产环境多余 |
| 无 Dockerfile / 健康检查 / 指标 | 部署与观测不可行 |
| `.gitignore` 对已跟踪文件无效 | 运行时数据变更仍会进 `git status` |

## 5. 速查

### 环境变量

| 变量 | 必填 | 默认 | 用途 |
|---|---|---|---|
| `BOT_TOKEN` | ✅ | — | 缺失直接退出 |
| `TEST_CHANNEL` | 分享必填 | 空 | `SHARE_MODE=test` 时的分享目标；也是中转频道回退值 |
| `TRANSIT_CHANNEL` | 审核必填 | `TEST_CHANNEL` | 待审申请中转频道 |
| `FURRY_READING` | `prod` 必填 | 空 | 兽人阅读；评分达标时同时发这里 |
| `FURRY_NOVELS` | `prod` 必填 | 空 | 兽人小说；`prod` 模式下所有作品都发这里 |
| `SHARE_MODE` | 可选 | `test` | `test` / `prod` |
| `SHARE_SCORE_THRESHOLD` | 可选 | `7` | `prod` 模式下同时发兽人阅读的评分下限 |
| `FURRY_READING_NEW_GROUP` / `TEST_GROUP` | 可选 | 空 | 当前未使用 |
| `SHARE_COOLDOWN_DAYS` | 可选 | `3` | 同一作品分享冷却天数 |
| `FILE_CACHE_TTL_DAYS` | 可选 | `7` | `file_id` 缓存天数 |

### 命令

| 命令 | 作用 | 权限 |
|---|---|---|
| `/start` `/help` `/ping` | 欢迎 / 帮助 / 返回 chat_id 与语言 | 所有人 |
| `/down <链接>` | 等价于发链接 | 所有人 |
| `/review` | 重推全部待审申请到中转频道 | ⚠️ 当前无校验 |

> callback 动作（`dn` / `af` / `snp` …）与处理函数的完整对照见 **04 第 3.3 节**，此处不重复。
