# 07 · 配置与部署

> 面向：自己跑一份 Bot 的人、接手服务器的人、准备提 PR 的人
> 代码基线：2026-11-13（历史改写后提交号会变，故只记日期）
> 本文回答「怎么装、怎么配、怎么跑、怎么测、怎么守」。**改代码看 [04](04-如何改代码.md)，架构边界看 [03](03-项目架构说明.md)，用户视角看 [02](02-用户使用流程.md)。**

---

## 0. 一句话

Python 3.12 + `uv sync` + `.env` + `data/*.json`，一条命令前台跑起来：**没有数据库、没有 Web 服务、没有任务队列**，断电风险靠 JSON 原子写兜。

---

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Python | **3.12+** | `pyproject.toml` 的 `requires-python = ">=3.12"`；仓库带 `uv.lock` |
| 包管理 | 推荐 [uv](https://docs.astral.sh/uv/) | 没有 uv 也能用 `venv + pip`，见 §2 |
| 网络 | 能直连 `api.telegram.org` 与 `linpx.ink` | 抓 Linpx 用 aiohttp，**不读 `HTTP(S)_PROXY`**；只有 Telegram 侧（httpx）会读代理变量。部署前先 `curl https://linpx.ink/` 确认直连可用 |
| Bot 身份 | 一个 Bot Token | 从 [@BotFather](https://t.me/BotFather) 申请 |
| 频道 | 分享 / 审核各需要频道，且 **Bot 必须是频道管理员** | 权限不足时表现为「发不出去」，日志里有 Telegram 报错 |
| 磁盘 | `data/`（KB~MB 级 JSON）+ `files/novels/`（临时文件） | 作者全量下载会残留目录，需定期清 |

---

## 2. 安装

### 2.1 用 uv（推荐）

```powershell
uv sync
Copy-Item .env.example .env
```

```bash
uv sync
cp .env.example .env
```

`uv sync` 会按 `uv.lock` 建好 `.venv/`，后面所有命令都跑 `.venv` 里的解释器。

### 2.2 不用 uv

仓库**没有** `requirements.txt`，依赖清单以 `pyproject.toml` 为准：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -U pip
.venv\Scripts\python.exe -m pip install "python-telegram-bot>=22.8" "aiohttp>=3.14.5" "aiofiles>=25.1.0" "pyzipper>=0.4.0" "requests>=2.34.2" "python-dotenv>=1.2.4" "pytest>=9.2.0"
```

> `pytest` 目前写在运行时依赖里（见 [01 §2 P2](01-功能清单与缺口.md)），所以上面一起装了。

## 3. 数据目录

| 路径 | 是什么 | 要不要提交 |
|---|---|---|
| `data/*.json` | 运行时状态：三份名单、兽人作者申请、作者下架申请、`file_id` 缓存、分享记录 | **不要**。根仓库 `.gitignore` 里有 `data/*.json` |
| `data.example/*.json` | 模板。`furry_authors.json` 含一份公开的**兽人作者名单**；`black_authors.json` / `furry_request.json` / `files_cache.json` / `share_records.json` / `white_authors.json` 是空结构（`black_request.json` 模板里没有，首次运行会自动建） | 可以，它是模板 |
| `files/novels/` | 下载临时目录，上传成功后删除 | **不要**，已 gitignore |

首次运行时的行为：

- 任何缺失的 JSON 会被 `JsonStore` **自动创建**为空结构（`storage/json_store.py`），所以只填 `BOT_TOKEN` 也能启动，只是所有作者都不在名单里 → 全部走「申请」。
- 想让 Bot 开箱可用，把模板拷进 `data/`（只拷 JSON，别带 `data.example/.idea/` 那份历史残留）：

```powershell
New-Item -ItemType Directory -Force -Path data | Out-Null
Copy-Item data.example\*.json data\
```

```bash
mkdir -p data && cp data.example/*.json data/
```

`data/` 目录本身在仓库里是一个**独立的 git 仓库**（自带 `.git`、`.github` 工作流、`.gitignore`、`README.md`）。名单的备份 / 同步要进 `data/` 单独操作，根仓库只会把它看成未跟踪目录。

## 4. 配置项（`.env`）

从 `.env.example` 复制后填。`config.py` 只用 `python-dotenv` + `os.environ`，没有额外校验。

| 变量 | 必填 | 默认 | 作用 |
|---|---|---|---|
| `BOT_TOKEN` | ✅ | — | Bot Token。**缺失时进程直接 `SystemExit`** |
| `TEST_CHANNEL` | 分享 / 审核必填 | 空 | `SHARE_MODE=test` 时唯一的分享目标；也是 `TRANSIT_CHANNEL` 的回退值 |
| `TRANSIT_CHANNEL` | 审核必填 | `TEST_CHANNEL` | 待审申请（兽人作者申请、作者下架申请）的中转频道 |
| `FURRY_READING` | `prod` 必填 | 空 | 兽人阅读频道；`prod` 下评分达标时同时发这里；也是分享文案里的「支持频道」 |
| `FURRY_NOVELS` | `prod` 必填 | 空 | 兽人小说频道；`prod` 下所有分享都发这里 |
| `SHARE_MODE` | 可选 | `test` | `test` / `prod`。**任何不等于 `prod` 的值都按 `test` 处理** |
| `SHARE_SCORE_THRESHOLD` | 可选 | `7` | `prod` 下同时发 `FURRY_READING` 的评分下限（`score` 目前恒为 `None`，这条分支实际走不到） |
| `SHARE_COOLDOWN_DAYS` | 可选 | `3` | 同一作品重复分享的冷却天数 |
| `FILE_CACHE_TTL_DAYS` | 可选 | `7` | `file_id` 缓存有效期；命中就直接复用，不再上传 |
| `FURRY_READING_NEW_GROUP` / `TEST_GROUP` | 可选 | 空 | **当前没有任何代码读取**，配了也不生效 |

关于默认值的三个坑：

1. `SHARE_COOLDOWN_DAYS` / `FILE_CACHE_TTL_DAYS` 在 Store 里另有兜底默认（7 / 30 天），但 Bot 运行时**永远**传 `config.py` 的值（3 / 7），以本文表格为准。
2. `TRANSIT_CHANNEL` 为空时静默回落到 `TEST_CHANNEL`；两个都空 → 申请卡片发不出去，只在日志里 `warning`（见 [01 §2 P0](01-功能清单与缺口.md)）。
3. 启动时**没有配置校验**：填错的频道 ID 不会立刻报错，直到真正发消息才失败。

频道既可以填数字 ID（`-1001234567890`），也可以填公开频道的 `@username` —— 都是原样交给 Telegram API。

### 4.1 最小可运行

```dotenv
BOT_TOKEN=123456:AA...
TEST_CHANNEL=-1001234567890
```

此时分享只发 `TEST_CHANNEL`，审核也用 `TEST_CHANNEL`。适合本地调试。

### 4.2 生产形态

```dotenv
BOT_TOKEN=123456:AA...
SHARE_MODE=prod
FURRY_NOVELS=@furry_novels
FURRY_READING=-1001234567891
TRANSIT_CHANNEL=-1001234567892
SHARE_COOLDOWN_DAYS=3
FILE_CACHE_TTL_DAYS=7
```

> `prod` 下因为 `score` 从未赋值，实际只会发 `FURRY_NOVELS`；想同时发 `FURRY_READING` 需要先实现评分（见 [01 §4](01-功能清单与缺口.md)）。

## 5. 启动

```powershell
.venv\Scripts\python.exe bot.py
```

```bash
.venv/bin/python bot.py
```

- 日志走 stdout（`logging.basicConfig`，INFO 级）；`Bot 启动中……` 之后进入 **long polling**。
- `drop_pending_updates=False`：停机期间的消息会在重启后补处理。
- 并发：`Application.builder().concurrent_updates(CONCURRENT_UPDATES)` 并行处理 update；`config.py` 默认 8，可用环境变量 `CONCURRENT_UPDATES` 调（1 = 串行）。不要用 `True`（PTB 里等于 256 路）。
- `post_shutdown` 通过 builder 注册（v20+ 里它不是 setter），退出时关掉复用的 aiohttp 会话。
- 同一链接的下载由 `DownloadService` 内的 `asyncio.Lock` 串行（并发 dst 会写同一个输出文件），不同作品仍并行。
- 不启动轮询、只验证装配：

```powershell
.venv\Scripts\python.exe -c "import bot; print('import ok')"
```

### 5.1 上线自检清单

| # | 检查 | 不满足时的现象 |
|---|---|---|
| 1 | `.env` 里 `BOT_TOKEN` 有效 | 无效 Token 在 `run_polling` 阶段抛 `Unauthorized` |
| 2 | Bot 已加入所有频道并设为管理员 | 分享 / 中转消息发不出去，日志里 `Forbidden` / `chat not found` |
| 3 | 中转频道建议设为**私有** | 管理员判定看该频道的成员身份，私有能少一堆误触 |
| 4 | `data/furry_authors.json` 非空 | 空名单 → 所有作者都要走申请 |
| 5 | `files/novels/` 可写、磁盘有余量 | 抓取 / 保存失败 |
| 6 | 服务器能直连 `linpx.ink` | 下载提示抓取失败，日志里 `异步请求 JSON 失败` |

## 6. 测试

```powershell
.venv\Scripts\python.exe -m pytest test -q
```

现状（2026-11-13 实测）：**220 项 → 217 passed / 3 skipped**，全绿。

| 跑法 | 命令 | 结果 |
|---|---|---|
| 全量 | `pytest test -q` | 217 passed / 3 skipped |
| 跳过真实 API 用例 | `pytest test -q --ignore=test/test_linpx.py` | 209 passed |
| 只跑缩进守门 | `pytest test/test_style.py -q` | 1 passed |
| 只跑键盘接线 | `pytest test/test_keyboard_routing.py -q` | 4 passed |

- `test/test_linpx.py` 里有 3 条会真的打 Linpx API，默认 skip；要跑就设 `LINPX_LIVE`：

```powershell
$env:LINPX_LIVE = "1"
.venv\Scripts\python.exe -m pytest test/test_linpx.py -q
```

```bash
LINPX_LIVE=1 .venv/bin/python -m pytest test/test_linpx.py -q
```

- 「改哪层该跑哪个测试」的映射表在 [04 §5.1](04-如何改代码.md)。
- 测试不依赖真实 Bot Token，除被 skip 的 3 条外不联网。

## 7. 代码风格

| 规则 | 由谁保证 |
|---|---|
| `.py` 一律 **Tab 缩进（Tab = 4 列）** | `.editorconfig` + `test/test_style.py`（扫全仓，行首缩进含空格即失败） |
| UTF-8、LF、去行尾空格、末行换行 | `.editorconfig`（`core.autocrlf=true`，仓库内存 LF） |
| `__pycache__/`、`*.py[cod]`、`.pytest_cache/`、`files/`、`*.zip`、`.env`、`.idea/` | `.gitignore` |

- `test_style.py` 走 `tokenize`，只看真正产生 token 的代码行，**docstring / 注释里的缩进不算违规**。
- PyCharm 两个开关：`Enable EditorConfig support` 勾上、`Detect and use existing file indents for editing` 取消。
- 为什么不提交 `.idea/`、想改成 4 空格怎么改：见 [04 §5.4](04-如何改代码.md)。
- 除此之外**没有** lint / format / type 配置（P2，见 [01 §2](01-功能清单与缺口.md)）。

## 8. 部署

### 8.1 现状

- 单进程、long polling、前台运行；重启只会丢内存里的 `_inflight`（分享并发保护）和下载串行锁，业务数据都在 JSON 里。
- 仓库 `deploy/` 目录**是空的**：没有 Dockerfile、没有 systemd unit、没有健康检查 / 指标（见 [01 §2 P2](01-功能清单与缺口.md)）。
- 想上线，最省事的是「一台机器 + 进程守护」。下面这份 unit 是**参考写法，不在仓库内**：

```ini
[Unit]
Description=FurryReadingBot
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/FurryReadingBot
ExecStart=/opt/FurryReadingBot/.venv/bin/python bot.py
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now furryreadingbot
journalctl -u furryreadingbot -f
```

### 8.2 运维清单

| 频率 | 做什么 |
|---|---|
| 每天 | 看日志里的 `更新处理出错` / `Forbidden` / `异步请求 JSON 失败` |
| 每周 | 清 `files/novels/`（作者全量下载残留目录）；备份 `data/*.json` |
| 改名单后 | 名单 mtime 热加载，**不用重启**，下一条消息即生效 |
| 换 Token / 换频道 | 改 `.env` 后重启进程 |
| 撤销管理员 | 按频道权限判定，缓存 60 秒内生效 |

> 手工拉黑（直接改 `black_authors.json`）**不会**删除频道里的历史分享；只有作者下架申请核验通过（`rby`）才会自动删。清理历史分享前先看 [02 §4.3](02-用户使用流程.md)。

## 9. 常见启动 / 运行问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `请设置环境变量 BOT_TOKEN` | `.env` 没建或变量为空 | 复制 `.env.example` 并填写；`config.py` 只读进程环境与 `.env` |
| 启动报 `ModuleNotFoundError: telegram` | 用了系统 Python 而不是 `.venv` | 用 `.venv\Scripts\python.exe bot.py` |
| 申请点了没反应、日志 `未配置中转频道` | `TRANSIT_CHANNEL` / `TEST_CHANNEL` 都为空 | 至少配一个，且 Bot 是管理员 |
| 分享提示「没有可用的分享频道」 | 当前模式对应的频道变量为空 | `test` 看 `TEST_CHANNEL`，`prod` 看 `FURRY_NOVELS` |
| 下载失败、日志 `异步请求 JSON 失败` | 服务器连不上 `linpx.ink`，或链接不是 Linpx | 换网络 / 加直连；确认链接域名 |
| 测试里 3 条 skip | 真实 API 用例默认关闭 | 需要时设 `LINPX_LIVE=1` |
| `test_style.py` 失败 | 某处用了空格缩进 | 按报错的文件:行号改成 Tab |
