# 08 · 标签词表（`tags.toml`）

词表只做一件事：**把来源站点的自由写法映射成规范名，并按需要展开上级标签**。
日常维护只需要 `tags.toml` + `sources/tags.py`，没有别的脚本参与；
认不出的写法由解析层自动留档到 `data/unknown_tags.json`，人工判断后再补 `aliases`。

## 1. 文件角色

| 文件 | 运行时需要 | 作用 |
|---|---|---|
| `data/tags.toml` | **是** | 唯一词表源文件 |
| `sources/tags.py` | **是** | 加载 / 校验 / 解析 / 留档的唯一实现（`Vocabulary`、`load_vocabulary`、`get_vocabulary`、`display_tags`、`unknown_tags`、`forget_unknown_tags`、`normalize`） |
| `storage/unknown_tags.py` | **是** | 未识别标签的落盘表（`UnknownTagStore`：`count` 按作品数累加、首末时间、显式 `prune()`） |
| `data/unknown_tags.json` | 自动生成 | 未识别写法的留档，供人工判断后补 `aliases`；**不自动淘汰** |
| `data.example/tags.toml` | 否 | 小样例，试规则用；同时是 `test/test_tags.py` 的守门样本 |
| `test/test_tags.py` | 否 | 规则单测 + 两份词表的 `errors == []` 守门 |


## 2. 规则速览

| 类型 | 怎么判定 | 可用字段 | 输出 |
|---|---|---|---|
| 复合标签 | 有 `parts` | `parts` | 只输出拆开后的基础标签，**自己不出现** |
| 原子标签 | 无 `parts` | 可选 `parents` | 输出自己 + 上级的传递闭包 |

**不变量：输出集合里只有原子标签。** 复合标签是输入侧的拆分规则，不是输出词汇。

`parts` 与 `parents` **互斥**，且 `parts` 不能指向另一个复合标签（不支持嵌套）。

```toml
[GayFurry]                       # 复合：ケモホモ → #Gay #Furry
group = "orientation"
order = 240
parts = ["Gay", "Furry"]
aliases = ["ケモホモ", "兽人同性"]

[Transfur]                       # 原子 + 上级：兽化 → #Furry #Transformation #Transfur
group = "plot"
order = 780
parents = ["Transformation", "Furry"]
aliases = ["兽化", "TF"]

[R18G]                           # 上级会传递：CBT → #R18 #R18G #CBT
parents = ["R18"]
```

## 3. 全局配置与字段

```toml
[meta]
schema = 2
match = "casefold"
parts_mode = "split"
# groups = ["rating", "orientation", "species", "act", "plot"]   # 可选：显式规定输出组序
```

| 字段 | 说明 |
|---|---|
| `schema` | 词表结构版本，目前只支持 `2`；填别的直接 ERROR |
| `match` | 只支持 `"casefold"`；归一规则写死在 `sources/tags.py:normalize()`，这里只是声明 |
| `parts_mode` | `split`（默认）只拆成基础标签、不继承上级；`inherit` 拆分后按普通标签继续解析 |
| `groups` | 可选。输出时的组顺序；不写就按词表里 `group` **首次出现的顺序** |

| 字段 | 适用 | 类型 | 说明 |
|---|---|---|---|
| 表名 | 全部 | — | 规范名，也是输出的 hashtag；`^[A-Za-z][A-Za-z0-9_]*$`；casefold 后全局唯一 |
| `group` | 建议 | string | 分组，决定输出顺序的第一关键字 |
| `order` | 建议 | int | 组内排序权重，越小越靠前；**必须写整数**（写字符串会 ERROR） |
| `parts` | 仅复合 | string[] | 拆分目标；自身不输出；不能指向复合标签 |
| `parents` | 仅原子 | string[] | 上级；输出取传递闭包；上级必须是原子标签 |
| `aliases` | 全部 | string[] | 来源写法（可带空格、中日文、缩写） |

**输出顺序 = `group` 序 → `order` → 名字。** `order` 是词表内的全局序号（各组数值可以交叉），
所以想让某组排在前面，改的是 `group` 的顺序（或 `meta.groups`），而不是把整组 order 重排。

## 4. 匹配规则

对任意输入字符串：① NFKC 归一（全角数字/字母）→ ② 去掉前导 `#` / `＃` → ③ 空白折叠为单空格 → ④ `casefold()`。

然后：

1. **整串**命中别名索引 → 直接返回该规范名（所以别名可以带空格，如 `Gay Furry`）；
2. 否则按分隔符 `[\s/,，、|;；]+` 拆开，**每一段都命中**才接受；
3. 否则视为残余（residual），不映射。

两条容易误解的点：

- **简繁、平片假名、异体写法运行时不做互转。** 要覆盖的写法必须写进 `aliases`。
- **不做子串匹配。** `猫耳` 不会命中 `Cat`（`猫` 才是别名），所以单字别名（`兽`、`熊`、`虎`）的风险仅限于「来源标签恰好就是这个字」，不会误伤长词。

## 5. 编写指南

新增原子标签：

```toml
[NewTag]
group = "act"
order = 999
aliases = ["中文写法", "繁體寫法", "English Alt"]
# parents = ["SomeParent"]    # 有固定上级时才写
```

新增复合标签（仅当「名字就是若干基础标签的拼接、且输出里不需要保留这个名字」）：

```toml
[FooBar]
group = "plot"
order = 999
parts = ["Foo", "Bar"]
aliases = ["foobar", "Foo Bar", "某某复合写法"]
```

别名与命名：

- 同一别名（normalize 后）全局只能属于一个规范名；
- 不要把规范名自己写进 `aliases`（会 WARN）；
- 简体、繁体、日文、空格写法分别列出；空字符串别名非法；
- 表名输出就是 hashtag，大小写会原样显示：除 `format` / `lang` 组（`#en` `#zh` `#txt` 用小写）外，一律 PascalCase（小写会 WARN）；
- `order` 建议留间隔（+10），方便以后插入。

## 6. 校验

校验在 `Vocabulary` 构造时完成（`load_vocabulary()` = 读文件 + 校验），**没有额外命令行工具**：
改完词表跑测试即可，CI 跑的也是同一条。

```bash
pytest test/test_tags.py -q
```

`test/test_tags.py` 里的三类用例：

| 用例 | 作用 |
|---|---|
| 规则用例（归一 / 拆分 / 闭包 / 匹配 / 各条校验） | 锁住 `sources/tags.py` 的行为 |
| `test_shipped_vocabulary_has_no_errors` | 守门：`data/tags.toml` 与 `data.example/tags.toml` 加载后 `errors == []`，改坏就红 |
| `test_documented_examples` | 本文档里的解析示例回归，防止文档与词表漂移 |

`Vocabulary` 会检查，分两级：

**ERROR（阻断上线）**

- `schema` / `match` / `parts_mode` 取值非法
- 表名不合法，或 casefold 后与其他表名重复
- `parts` / `parents` / `aliases` 不是字符串数组；引用不存在、自指、`parts` 嵌套复合标签
- `parts` 与 `parents` 同时非空
- `parents` 指向复合标签
- `parts` / `parents` 成环
- 别名为空，或 normalize 后撞车
- `order` 不是整数、`group` 不是字符串

**WARN（需人工确认，不阻断）**

- 表名不是 PascalCase（`format` / `lang` 组除外）
- `meta.schema` 没写（按 `2` 处理）
- `aliases` 内部重复，或把规范名自己写进 `aliases`
- `name` 与 `parts` 拼接不一致（提醒确认该用复合还是原子 + parents）
- `group` 没列进 `meta.groups`（会排到最后）

怎么读校验结果：

```python
import logging

from sources.tags import load_vocabulary

logger = logging.getLogger(__name__)

vocab = load_vocabulary()            # 默认 data/tags.toml
if vocab.errors:                     # 结构性错误：拒绝启动（或至少告警）
	raise SystemExit("标签词表有误：" + "；".join(vocab.errors))
for warning in vocab.warnings:       # 命名风格 / 重复别名：打日志，不阻断
	logger.warning("标签词表：%s", warning)
```

有 ERROR 不应上线；WARN 需人工确认（多半是命名风格或重复别名）。

## 7. 运行时接入

```python
import logging

from sources.format import format_tags
from sources.tags import display_tags, get_vocabulary

logger = logging.getLogger(__name__)

vocab = get_vocabulary()           # 进程内唯一实例；首次加载即把 errors / warnings 写进日志
if vocab.errors:                   # 结构性错误：拒绝启动或告警
	for error in vocab.errors:
		logger.error("标签词表：%s", error)

caption_tags = format_tags(display_tags(novel.tags))   # → "#Furry #Gay #Transformation ..."
```

`display_tags()` 一步做完：解析 → 按 `group`/`order` 排序 → 截断 8 个 → 未识别写法原样追加 → 落盘记账。

### 7.1 职责边界

| 入口 | 做什么 | 不做什么 |
|---|---|---|
| `Vocabulary.resolve()` | 纯解析：规范名 → 标签集合 | 不写盘；未知名只返回空集合（打 debug） |
| `Vocabulary.resolve_all()` | 解析 + **留档**：来源写法 → 规范名，未识别的写进 `data/unknown_tags.json`（`record=False` 关掉） | 不截断、不带出 residual |
| `display_tags()` | 展示策略：排序 + `limit` + 未识别写法原样带出（内部调 `resolve_all`，`record` 透传） | 不自己记账（避免一次调用记两遍） |
| `storage.unknown_tags`（`UnknownTagStore`） | 持久化：`count` 累加、首末时间、显式 `prune()`、原子写 | 不判断「什么算未识别」；归一键由 `sources.tags.normalize()` 产生 |

一句话：**留档是「解析」的副作用，不是「展示」的责任**——只要业务走到 `resolve_all()`（`display_tags()` 内部也走），未识别写法就不会漏记；只有 `record=False` 才关。

接入时的几个决策（现在的代码还没接线）：

- **只加载一次**：直接用 `sources/tags.py` 的 `get_vocabulary()`（内部 `lru_cache`，首次加载就把 errors / warnings 写进日志），别每篇作品重读 TOML；
- **residual 原样带出并落盘**：`resolve_all()` 默认把未识别的写法写进 `data/unknown_tags.json`（`unknown_tags()` 读、`forget_unknown_tags([...])` 按条销账、`clear_unknown_tags()` 全清、`store.prune()` 手动瘦身，**不会自动淘汰**）；`display_tags()` 再把它们按全角归一 + 去前导 `#` 追加在规范标签之后，`limit` 只约束规范标签；`record=False` 只解析不留档；
- **限制输出数量**：`act` / `plot` 组很细，一篇文可能命中十几个标签，建议取前 6~8 个（列表已排序，直接切片）；
- **SFW 与 R18 互斥**：命中 `R18` / `R18G` 时丢掉 `SFW`，词表层不做这条业务规则；
- 词表是数据，`data/` 是独立 git 仓库：改完要在 `data/` 里单独提交；`/sync` 脚本只 `git add -- ':(glob)*.json'`，**不会带上 `tags.toml`**。

## 8. 常见坑

- 运行时**不要**再维护一份别名 JSON；索引由 `Vocabulary` 建；
- **留档是 `resolve_all()` 的副作用**：只要解析过就不会漏记，`display_tags()` 只是展示；`record=False` 才关；
- 传自定义词表试规则时配 `record=False`：否则「生产词表不认识」的写法会被记进 `data/unknown_tags.json`；
- 运行时**不要**做 OpenCC 简繁转换；要覆盖的写法写进 `aliases`；
- 业务代码**不要**自己实现另一套 `parts` / `parents` 语义，以 `sources/tags.py` 为准；
- 依赖只有标准库 `tomllib`（Python 3.12），不需要装 extra；
- 最小可运行例子见 `data.example/tags.toml`（`parts_mode = "split"` 下：`ケモホモ` → `#Gay #Furry`，`CBT` → `#R18 #R18G #BDSM #CBT`，`兽化` → `#Furry #Transformation #Transfur`）。
